## 登录与复用

1. 启动工具，在账号管理添加平台和备注。
2. 点击“登录 / 打开后台”，在工具打开的专属 Chrome 中自行扫码。无需复制 Cookie。
3. 扫码完成后后台自动识别，无需点击“核验身份”。知乎优先通过已登录网页的当前用户请求读取身份，个人菜单链接作为备用；这不是开发者开放 API，不需要另配 OAuth。识别检查不刷新页面、不抢焦点。若遇平台验证或接口变化，工具保留“正在识别登录”状态并暂停发布，不冒认连接成功。
4. 关闭重开工具后，打开相同账号继续使用。每次准备发布和最终提交前再次检查账号身份。
5. “停用连接”关闭窗口并停用执行，保留本机环境，不等于平台撤销登录。再次打开后台后自动重新识别。扫码识别成功后停止轮询；创建任务时已打开的登录环境允许先入队，执行时补查并绑定身份，尚未扫码则任务暂停等待登录。

### 创建时的占用处理（0.7）

创建任务只保存内容与选项，不同步启动或切换浏览器。账号正在同步或其他任务正在上传时，图文/视频任务也可正常入队；重复请求复用原任务。后台按钮会排队等待浏览器操作完成，页面显示“处理中”。实际执行仍串行，执行前及提交前核对账号。账号有待人工确认或结果未知的任务时，新任务先排队，避免覆盖原发布页面。已停用、错号和重复绑定账号不能以延迟检查绕过。

默认需要 Chrome。使用 Edge：启动前设置 `$env:MATRIX_BROWSER_CHANNEL = 'msedge'`。不要同时启动两份工具占用同一账号目录。

身份定位在 `config/identity-selectors.json`。初始选择器未用真实账号核验，需针对当前后台本人资料链接调整；不能选成推荐作者或任意作品作者链接。账号首次绑定平台 ID 后，身份不一致会阻断；同一平台身份不重复绑定。

## 页面适配与真实提交

### 静默执行与人工接管（0.5）

自动模式默认开启“静默执行自动发布”，不显示Chrome窗口；也可以取消此项进行可见执行。人工模式使用可见窗口。首次登录扫码仍需要可见窗口，后台识别成功后，自动任务会保存当前登录环境、关闭窗口并以headless方式重新打开同一账号目录。浏览器不会通过同时打开两个Profile副本来静默执行。

静默阶段遇到验证码、身份不明或页面变更时会暂停；不会绕过验证。点击任务的“打开任务浏览器”进行接管，会切回可见窗口。尚未提交的任务会恢复原文并等待你确认；可能生成新的平台草稿。已有提交记录或结果未知时只打开后台供核对，不重新填写或提交。

知乎发布入口优先使用配置定位，再匹配唯一的“发布 / 下一步 / 发布设置”按钮。若使用语义定位，先持久记录“正在打开发布设置”，确认面板出现后才继续；若中断或无法确认设置面板，进入结果待确认，禁止自动重试。同账号尚未提交的准备失败任务不阻塞新的排队任务；等待人工确认或结果未知的任务继续阻塞。

发布页“发布选项”提供两项选择：

- “发布前人工处理”：页面准备完成后暂停，打开任务浏览器补充封面、分区等内容，再点击“确认真实提交”。
- “工具直接完成发布”：点击“创建并直接发布”即按所选账号、内容和 AI 声明授权本次直接提交。准备后不再等待第二次确认；异常会暂停，提交结果不明不会重发。

AI声明需选择“勾选 AI 辅助创作”或“不勾选 AI 辅助创作”。知乎使用“创作声明”下拉菜单时，会展开并选择“包含 AI 辅助创作”，再读回该声明显示值；取消时选择“无声明 / 不声明”，已选的已识别非AI声明会保留。原checkbox界面则设置checkbox并读回。提交前再次核对，不会仅保存一个界面开关。演示账号只模拟所选流程，不操作真实平台。模式和声明随草稿保存，并随每次分发写入不可变快照和日志。

0.5.1 针对下拉菜单处理已展开、异步出现、按钮文字更新、React替换控件和隐藏旧选项等情况。只点击菜单选择项，不把“创作声明”操作误当最终发布。若点击后未回显所选声明，不算成功，停止投稿。

配置中的 `aiDisclosure.selector` 可指定平台声明checkbox的CSS选择器。留空时尝试按可访问名称匹配“AI辅助创作 / 人工智能生成”等checkbox；不存在、多匹配、无法设置时会暂停。若声明在发布设置弹窗内，在 `publishSteps` 数组配置用于**打开发布设置的非最终提交入口**，按顺序执行；不要把真正发布按钮放入该数组。平台是其他形态的控件时需要另行适配，不会猜测勾选结果。

手动模式准备阶段尚未找到声明控件时会提醒，在最终提交时必须匹配并确认状态；直接模式也遵守相同检查。旧任务未提供声明选项时保留旧行为，不自动改变平台状态。

`config/adapters.json` 每种内容类型含 `url`、`upload`、`title`、`body`、`submit`、`success`。代码使用 [Playwright Actions](https://playwright.dev/docs/input) 的 `setInputFiles`、`fill` 和 `click`；会话使用 [持久浏览器上下文](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context)。

初始 URL/选择器是待验证配置，不能视为平台端到端通过。修改后重启服务。定位不到或匹配不唯一时暂停，不自动取第一个元素。

真实账号的“创建分发任务”会向官方后台上传素材并尝试填写。文章 HTML 使用富文本粘贴，内嵌本地图片转换成图片数据，由目标编辑器处理；检测到基础格式丢失会暂停。准备完后检查图片和视频是否处理完成，以及封面、分区、话题、原创/转载、版权和商业声明。当前这些字段需要手工处理；平台可能重排或拒绝部分富文本样式与图片。

## Word 与富文本

长文章使用 Tiptap 编辑器，支持标题、强调、列表、链接、对齐、字体字号、颜色、图片与表格，平台版本独立保存。Word HTML 粘贴会保留编辑器能表达的结构；`.docx` 导入使用 Mammoth 转换，主要保留语义结构和基础格式，不保证字体、打印分页及所有Word布局完全一致。旧`.doc`、页眉页脚、浮动对象不支持。导入后检查再保存。富文本发布使用 HTML 剪贴板粘贴，会替换本机剪贴板内容。

通用适配器的 `submit` 和 `success` 默认均为 `null`，需在真实页面核实后配置。`flow: "zhihu-article"`、`"xhs"`、`"douyin"`、`"bilibili-video"` 使用内置流程，可按唯一按钮的可访问名称和本次明确成功提示完成定位。抖音仅允许官方上传/视频编辑网址；不能只凭跳转到作品列表或看到旧作品“审核中”当作本次成功。提交前还会检查当前账号身份、页面 URL、文案快照和按钮是否可用，已有成功标志时也会阻断。

0.4.1 中知乎长文章使用 `flow: "zhihu-article"` 内置流程，不再依赖上述通用 `submit` 配置：打开发布设置面板，在面板内寻找唯一的“发布 / 发布文章 / 确认发布”最终按钮，等待可用，处理所选 AI 声明后提交。支持 `/write` 和自动保存后的 `/p/<id>/edit` 编辑网址；最终跳转 `/p/<id>` 时记录稿件ID与链接，或记录本次提交后的成功/审核提示，均不冒认已审核公开。页面版本不匹配时保留明确错误。

富文本检查按文字和有效加粗、斜体等样式比较，兼容知乎使用 `span style="font-weight: bold"` 等标记。比较失败会在日志中给出字数/缺失格式类别，不记录正文。可在任务详情点击“重试未提交任务”重跑原任务；存在任何提交记录的任务不得这样重试。

人工模式的任务页“确认真实提交”触发最终点击；直接模式由创建任务时选定的执行计划触发。只有点击后显示所配置的成功标志才记录“平台已提交”；未提取真实稿件 ID、链接或审核结果时不制造这些数据。点击后超时进入结果待确认，不自动重发。

页面规则失败时可取消提交前任务，修正规则后重新创建分发意图；结果未知时先人工核对稿件，不要直接重新投稿。

## 会话存储

每账号目录：`.data/profiles/<内部账号ID>/`。Chrome 自己管理 LocalStorage、IndexedDB 等站点数据。工具在身份核验、正常关闭时补存会话 Cookie 到 `matrix-session.dpapi`，使用 Windows CurrentUser DPAPI 加密，恢复时只补当前浏览器缺失且有效的 Cookie。

这不表示整个 Chrome Profile 都由工具额外加密。请使用本人 Windows 账户并保护磁盘，不分享 `.data/`。会话补存文件不能跨 Windows 用户使用。强制关机或直接关闭浏览器可能丢失最新补存状态，需要时重新扫码。正常退出使用 Ctrl+C。

## 验证边界

自动测试通过真实 Chrome 在拦截的模拟官方页面验证隔离、恢复、错号阻断、文件上传、文案与提交标志，并检查队列/API。未使用用户的真实账号登录或投稿。真实平台身份选择器、页面结构、媒体规则及完整投稿仍需逐项联调。
