# 浏览器操作节奏

日期：2026-11-12。

真实账号工作流默认在关键阶段之间增加有界随机等待：普通阶段 500–1400 毫秒，上传及提交前 1000–2800 毫秒。覆盖打开编辑器、选择发布入口、各字段填写、素材上传、知乎逐张图片导入、发布设置、创作声明及提交前身份复核。创作中心只读翻页也使用常规阶段间隔。

节奏等待发生在操作或复核之前。最终提交门禁与按钮点击之间不额外插入随机等待；身份、正文、图片、按钮状态和发布结果仍由原校验决定，不把等待完成当成操作成功。该功能缓和关键操作密度，不保证降低平台风控，也不修改浏览器指纹或隐藏自动化特征。

任务停止、页面关闭或运行时退出时，未完成的等待会取消。检查任务状态的粒度为 100 毫秒，原生浏览器动作本身仍沿用各自超时。准备与提交前进度回调检查任务控制权，避免停止后迟到进度把任务恢复成执行中。

服务启动前可配置：

|环境变量|默认值|用途|
|---|---|---|
|MATRIX_BROWSER_PACE|未设置即开启|设置 off 关闭随机等待|
|MATRIX_BROWSER_PACE_MIN_MS|500|普通阶段最小间隔|
|MATRIX_BROWSER_PACE_MAX_MS|1400|普通阶段最大间隔|

上传及提交前的区间是普通区间的两倍。参数必须为整数，0 ≤ 最小值 ≤ 最大值 ≤ 10000 毫秒；无效配置会阻止运行时启动。修改环境变量后重启服务生效。

BrowserRuntime 支持注入 pacing 设置；测试用 headless=true 的运行时默认关闭延迟，可通过 pacing.enabled=true 显式开启。受控回归可以用极短、可预测的区间验证逻辑，不需要等待生产环境的完整时长。随机等待不改变内容生成或恢复模型的调用预算，不替代重发冷却与发布频率策略。
