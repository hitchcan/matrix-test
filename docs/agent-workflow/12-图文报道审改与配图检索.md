# 图文报道、主 agent 审改与配图检索

2026-11-12。新增图文写作、排版、待审稿编辑及图片资料检索工作流，保留此前的视频生成、原素材发布及提交门禁。

## 当前工作流

选择独立写作模型时，图文流程为：

1. 可选：主 agent 根据主题或所选图片生成检索词，检索服务返回图片资料，下载并保存到素材库。
2. 主 agent 为外接写作模型编写提示词。
3. 外接写作模型起草文字及建议配图位置，保存为初稿。
4. 主 agent 根据事实、账号定位及平台形态实质审改：修改标题、导语、段落长度、语气和配图顺序，删除无依据的夸张表述，并给出审改说明。
5. 按段落、标题和图片块生成图文排版；图注及图片来源跟随对应图片，不统一堆在文末。
6. 新建页面默认保留为可编辑待审稿。用户可自行编辑，或提出意见再让主 agent 修改。确认某个版本后，才到时分发并经过原有发布门禁。

不选独立写作模型时，由主 agent 直接生成平台稿。视频场景及独立写作的原视频流程继续沿用此前逻辑，不强制增加图文编辑阶段。

需要文字中间穿插图片时，选择知乎或 B站的“长文章（正文穿插配图）”。小红书“图片笔记”仍按平台图库和配文发布，不能将其界面改成行间图片文章；主 agent 会保留配文与图片顺序。

## 页面使用

1. 保存主 agent 模型；如需外接写作，在“新建任务”勾选独立写作对话并选择配置。可以使用与 agent 相同的供应商和模型，调用仍是独立对话。
2. 填写主题、事实与账号定位，选择长文章目标。新闻式是写作与排版风格，不代表系统已经核实新闻；正文使用用户提供的事实与资料，不根据配图编造事件、时间、数字或引语。
3. 上传或勾选素材库图片，或者勾选“让主 agent 按主题检索图片资料”。可只按主题检索，不必预先勾选图片。
4. 要依据给定图片补充找图，勾选“结合所选图片理解主题再检索”，并为主 agent 启用图片输入能力。原图片先交视觉 agent 生成语义检索词；这不是反向搜图或身份识别。原图文件不会直接上传到图片检索网关。
5. 保留“生成后保留为可编辑待审稿”。运行完成后打开“查看各账号成品”，点击“编辑 / 让agent修改 / 确认发布”。
6. 可修改标题、各段文字和图注；上移、下移或移除段落和图片；从本次候选图片中插入图片。保存后仍是待审，不立即分发。
7. 在修改意见栏提出具体要求，例如缩短标题、删除重复背景或调整图片位置，点击让 agent 再审改。失败或中断时保留上一版，不用新内容覆盖旧版。
8. 查看已保存的图文排版、外接初稿、主 agent 审改说明及历史版本，确认后进入发布流程。若设置为“发布前人工处理”，仍遵循平台提交前的人工步骤。

取消保留待审稿时，主 agent 审改后的成品直接按原策略分发。外接模型初稿不会在审改完成前直接发布。已分发稿件在此处不可覆写；版本校验会拒绝旧页面覆盖新稿。

## 图片检索与来源

默认通过 Wikimedia Commons 检索，读取图片元数据的方法依据 [MediaWiki Imageinfo API](https://www.mediawiki.org/wiki/API:Imageinfo)。当前筛选明确的 CC0、公有领域或 CC BY 图片，跳过缺少必要来源、作者或许可信息的候选。Commons 图片只从固定图片主机下载。

每个目标最多两个检索词、最多补充四张图。图片下载有超时和体积限制，不跟随重定向，不把检索服务 API Key 发送给图片站。图片保存到素材库时同时记录来源页面、图片地址、作者、许可、许可链接、检索词和归档时间。素材库显示来源信息；用户备注仍可单独编辑。

外部检索得到的图片强制标注“资料配图（非本次事件现场）”，并在图注中保留作者、许可及来源。模型或手工改稿不能通过省略图注字段删除这些自动署名。素材库中此前检索归档的图片再次用于任务时，也会载入来源信息。

检索结果只作为图片资料，不用于证明新闻事实。没有找到可用图片、检索服务失败或返回越权图片 ID 时会阻断，不自动把无配图正文当作完整图文发布。

本机本轮直接访问 Commons 的请求超时，真实联网检索和下载尚未验收。可先使用素材库图片，或在“图片检索服务配置”中选择可达的自有 JSON 网关。本轮受控测试不代表公网服务可达。

## 自有图片检索网关

在配置中填写完整检索接口、可选 API Key，以及允许下载图片的主机名（英文逗号分隔，不支持通配符）。网关只接收 agent 生成的检索词。

POST 到配置接口，使用可选 Bearer 鉴权：

```json
{"queries":["computer desk"],"limit":3}
```

返回：

```json
{
  "images":[{
    "name":"电脑资料图",
    "imageUrl":"https://images.example.com/photo.jpg",
    "pageUrl":"https://source.example.com/photo",
    "author":"Photo Author",
    "license":"CC BY 4.0",
    "licenseUrl":"https://creativecommons.org/licenses/by/4.0/",
    "description":"画面内容与适用主题"
  }]
}
```

图片需要 HTTPS 地址，且主机在用户配置的下载范围中。返回候选仍经过来源、许可及数量校验。密钥不返回页面、不进入 agent 上下文，切换接口或供应商时不继承旧密钥。单次工作流开始时捕获检索服务配置，中途修改只影响后续任务。

## 预算与持久化

图文使用独立写作对话时，预留三次 LLM 调用（规划、起草、主 agent 审改）；开启检索另预留一次检索规划调用。每次追加 agent 修改再预留一次，手动编辑不调用模型。新建页面按所选目标计算建议预算，并为待审目标留出一轮追加审改空间；用户手工设置的上限仍优先。服务仍在发出模型请求前检查调用次数和费用预留。

旧运行继续使用保存的快照。旧模板单纯启停时保留旧两次调用语义；在新界面重新保存后使用新的审稿设置。API 兼容字段 editorialReview=false 用于旧两次调用流程；新任务默认启用主 agent 审稿。

SQLite 迁移17增加初稿、授权图片、版本号、审稿阶段和反馈，以及 workflow_artifact_versions 版本记录。asset_sources 保存图片来源，image_search_settings 保存本机检索配置。待审、修改中及未分发状态保护素材和账号引用；停止运行会取消尚未分发（包括已阻断）的目标，不清除历史与提交次数。

网络等待期间可停止任务；迟到的审稿或修改结果不能恢复取消状态或开始发布。重启后保留初稿和已保存版本，不自动重放结果不明的 LLM 调用。修改中断会回到待审并保留上一版。

## 接口

TaskSpec 新增：

```json
{
  "editorialReview":true,
  "reviewBeforePublish":true,
  "imageSearch":{"enabled":true,"useReferenceImages":true,"maxImages":3}
}
```

成稿 blocks 使用：

```json
[
  {"type":"paragraph","text":"报道导语"},
  {"type":"image","assetId":"本次授权图片ID","caption":"图片说明"},
  {"type":"heading","text":"背景信息"},
  {"type":"paragraph","text":"后续段落"}
]
```

不接受模型提供的任意图片 URL 或 HTML。旧 body/assetIds 输出仍可用，服务转换为段落与配图块。

- POST /api/runs/{runId}/targets/{targetId}/edit：expectedRevision、title、blocks。
- POST 同一路径 /revise：expectedRevision、feedback。
- POST 同一路径 /approve：expectedRevision。
- agent 工具 edit_artifact、revise_artifact、approve_artifact 复用相同服务；工具中 runId 参数名为 id。
- GET/POST /api/image-settings：读取脱敏检索配置或保存 provider、endpoint、key、downloadHosts、clearKey。

未待审、已分发或版本不匹配会拒绝修改。调用次数、费用上限和提交账本不会被改稿重置。
