# 微信视频号浏览器接入

2026-11-14。用户提供视频号目录下的 HTML 及视频标注展开截图，明确沿用现有浏览器路线。当前实现仅支持视频内容。

## 使用

1. 账号管理选择微信视频号，添加后在独立 Chrome 窗口扫码并选择对应视频号。账号环境按原有机制隔离、持久化。
2. 内容工作室选择一个视频素材及视频号账号，可填写视频号专属短标题和描述。短标题与描述分别映射后台对应字段，不自动截断或合并。
3. 明确选择 AI 辅助创作：勾选时选择“含AI生成内容”；不勾选时对空标注或已有 AI 标注选择“无需标注”，已有明确非 AI 标注保留。只读取 select-display 当前值，不能用菜单中存在同名选项证明设置成功；菜单关闭后才继续。
4. 人工模式在提交前等待用户确认；自动模式复核身份、文案、视频标注及按钮状态后，通过原 SQLite 提交门禁执行最终发表。
5. 出现验证或页面不匹配时暂停，由工作台打开浏览器人工处理。最终点击后没有明确成功回执则标记结果待确认，不自动重发。不会读取或填写验证码。

本机定时沿用原调度器，发表前要求视频号页面仍选择“不定时”。位置、合集、链接、活动、封面及平台原生定时未新增自动设置，沿用页面当前值或人工处理。素材仍遵守本工具的文件大小限制，不因平台截图显示更大上限就放宽。

## 依据与结构

主文件：wechat-channels.mjs。平台内部标识：channels。

- 保存 HTML 包含开放 Wujie Shadow DOM；使用 Playwright 原生 Locator 穿透，不能把保存页面当作可执行应用直接运行。兼容同源官方 iframe 内的唯一编辑器，多个候选则拒绝选择。
- 作品描述：.post-desc-box .input-editor[contenteditable]。短标题：placeholder 为“填写短标题有机会获得更多流量”的输入框。
- 视频标注：.post-with-mark-tag .mark-tag-select，菜单项为 .mark-tag-option 内的 .option-main。根据用户提供的展开状态确定目标文字。
- 最终按钮：可见且名称精确为“发表”的 button；同时检查原生禁用、aria-disabled 与 weui-desktop-btn_disabled 状态，排除其他弹窗确认按钮。
- 保存的官方脚本确认 auth_data 返回 data.finderUser，当前主体字段为 finderUsername、nickname。工具仅观察官方页面自行请求的 /cgi-bin/mmfinderassistant-bin/auth/auth_data 成功响应，要求 errCode=0；不重放接口，不以昵称、本地存储或 Cookie 存在推断本人身份。

## 2026-11-17：身份核验失败修复

现场：扫码登录后账号一直停在「等待扫码 / 识别登录」。视频号的身份完全依赖页面自己请求的 `auth_data` 响应，而原实现要求**精确等于** `/cgi-bin/mmfinderassistant-bin/auth/auth_data` 且无查询参数，平台追加缓存参数后即失效；同时监听只覆盖打开时的首个标签页。

修复：改为按控制台命名空间与前缀匹配（`/cgi-bin/mmfinderassistant-bin/` 下 `auth|account|user|self|finder` 路径），允许查询参数；响应字段兼容 `finderUser` / `finder_user` / `userAttr.finderUser` 及 `finderUsername` / `finder_username` / `username`；保留 `errCode` 非 0 时忽略。身份监听扩展到该账号浏览器环境的所有标签页。内容类接口（如 `post/get_feed`）里的其他作者不会被采信。

失败诊断：核验失败时终端打印页面地址与最近 12 条同源请求路径（每账号最多 30 秒一条），用于确认页面实际调用的接口名。

受控测试 `test/platform-identity.test.mjs` 覆盖带查询参数的 `auth_data`、内容接口不误判、错误码忽略。

## 2026-11-17 第二轮：/platform 页面不请求 auth_data

现场诊断日志显示，登录后的 `/platform` 页面**从未请求** `auth_data`，实际请求是：

- `/cgi-bin/mmfinderassistant-bin/report-perf?pf=web`（性能上报）
- `/cgi-bin/mmfinderassistant-bin/helper/hepler_merlin_mmdata?…`（埋点）
- `/micro/content/cgi-bin/mmfinderassistant-bin/post/post_list?…`（内容列表，微前端 iframe）
- `/micro/content/cgi-bin/mmfinderassistant-bin/collection/get_collection_list?…`（合集）

即：① 身份接口假设不成立；② 真实请求带 `/micro/content` 前缀，原先「路径必须以 `/cgi-bin/` 开头」的匹配把它们全部排除了。

改为四层读取，逐层收紧、都要求唯一：

1. **账号类响应**：`…/cgi-bin/mmfinderassistant-bin/` 命名空间下 `auth|account|user|self|finder` 路径（允许 `/micro/content` 前缀与查询参数），读 `finderUser` 等字段。
2. **页面内嵌数据**：扫描 `/platform` 及其同源 iframe 的 `document.documentElement.innerHTML` 与 `localStorage`，提取所有 `"finderUsername":"…"`；只接受唯一值。
3. **内容列表**：`post/post_list`、`collection/get_collection_list` 的响应里深度收集 `finderUsername`；只有全部条目同属一个账号时才采信，出现第二个作者即放弃。
4. **页面可见账号元素**：`channelsHomeIdentity` 读取 `.finder-uniq-id-wrap .finder-uniq-id#finder-uid-copy` 及其 `data-clipboard-text`。

诊断日志同时增加「页面内ID」字段：输出第 2 层在页面上实际找到的候选（最多 5 个）。若显示「无」，说明身份不在页面内嵌数据中，需要改为打开账号菜单后读取；若显示多个，说明页面里混有其他作者，需要进一步限定范围。

受控测试 8 项：快手带参、未登录、非账号接口；视频号带参 `auth_data`、内容接口不误判、错误码、`/micro/content` 账号接口、页面内嵌唯一/多值、内容列表单一作者/多作者。
