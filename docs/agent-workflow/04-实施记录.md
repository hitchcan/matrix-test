## W1、W2 已接入现有入口的部分

- POST /api/dispatch 在写事务中按 requestKey 检查稿件与目标账号集合。相同输入返回 200 和 reused，不同稿件或账号返回 409 和 request_key_conflict。创建成功返回 201 和分发 id。
- schema_migrations 记录迁移。publication_attempts 按 job_id 和 ordinal 唯一，历史 submitting 事件归并为一个首次尝试。已提交任务保留原回执。
- 首次最终动作前，提交服务将尝试、任务状态、事件一起提交。原有任务上限为一次。真实适配器等待门禁；演示与人工确认使用同一账本。点击超时不退还名额。
- GET /api/state 的 jobs[].usedAttempts 和任务详情显示已使用名额。对没有 submitting 事件或明确提交状态的历史任务，账本没有推定的提交时间。
- 在项目目录运行 npm start，打开终端显示的本机地址。Ctrl+C 停止。重启沿用原 dataDir，保留账本和历史任务。未知任务仍需到原账号后台核对后关闭。
- 测试入口为 npm run check 和 npm test。submission-service.test.mjs 检查重复迁移、历史未知、名额唯一与写入回滚。pipeline.test.mjs 检查分发幂等与冲突。browser.test.mjs 检查页面点击等待异步门禁及门禁拒绝。

## 第二轮实施：按账号保存核对策略并执行只读查稿

工作台创建稿件时可勾选「提交后核对创作中心」。默认关闭；旧任务采用关闭核对与零重发的快照。详情显示核对结果、最近核对时间、已关联稿件 ID、下次时间及停止核对按钮。已保存的重发策略暂不驱动最终发布动作。

程序启动自动执行迁移 2、3。每个 job 单独拥有 publication_intents、核对结果与可选的提交前作品 ID 快照。检查时间和截止时间从该账号的提交边界计算。工作台重新启动后，worker 领取到期任务；未结束的读取租约最多 60 秒后可重新领取。停止核对使用版本号，迟到的结果不能覆盖停止状态。待核对期间素材与账号删除仍受保护。

POST /api/dispatch 在原请求顶层接受 publicationPolicy，例如：

```json
{"verification":{"enabled":true,"firstCheckAfterSeconds":180,"checkIntervalSeconds":300},"retry":{"maxResends":2,"allowAbsentAfterTimeout":true,"cooldownSeconds":[1800,7200]}}
```

字段时间单位为秒。同一 requestKey 改动策略返回 409 request_key_conflict。无效策略返回 422 invalid_policy。GET /api/state 的每个 job 包含 publicationIntent，可读取 version、status、next_check_at、deadline_at、policy、lastObservation。POST /api/publications/{jobId}/stop 请求体为 {"expectedVersion":1}（使用当前版本），成功返回新状态。并发修改返回 409 version_conflict，当前无待核对动作返回 409 no_active_check。

```json
{"url":"https://creator.xiaohongshu.com/fixture-manager","complete":"#end","row":"article","idAttribute":"data-id","title":"h2","body":"p","time":"time","type":"i","status":"span","types":{"note":"图文"}}
```

complete 应唯一标识完整列表已加载；row 必须覆盖当前视图所有作品，time 元素有含时区的 datetime。现阶段适用于可一次完整读取的管理列表。提交前保存列表作品 ID，提交后核对账号、列表新增 ID、完整标题和正文、类型与发布时间。多个同标题新候选记录为歧义。匹配结果写入 verification_observations，可区分后台审核、定时和发布状态。复用原账号 context 中的独立页，重启后可重建。缺少基线、字段或完整标记均不能授权重发。

在 createStudio 中可注入 verifier 与 clock。无适配器时记录 unsupported_verifier。此阶段尚未实现基于分页和多状态覆盖的有效缺席判定、有限重发执行、模型恢复与内容生产；未进行真实账号或模型联调。

## 第三轮实施：有效缺席、最后查重与有限重发

本节更新前两轮记录里的重发限制。自动发布的既有稿件可在工作台启用核对，设置首次检查、检查间隔、观察期限、有效次数、重发次数和逐次冷却。首次提交和重发始终使用同一个 job ID。旧任务默认最多一次提交；演示和手工确认任务不会因发现缺席而自动提交。

**生效条件**　服务需要有能覆盖已发布、审核中、定时、草稿和拒绝状态的核对器。每条有效缺席必须具备正确账号、非空覆盖页数、从首次提交开始的时间范围和空候选列表。满足间隔、观察窗口及冷却后，重新准备原稿，在最终提交入口重新查重。门禁在写事务中复核 intent 版本、截止时间、有效证据与次数，追加 ordinal 后才执行最终点击。已发起的点击超时仍占名额。重发后发现多个匹配作品会记录疑似重复并停止。打开已尝试提交的任务浏览器接管会停止后续自动核对；从任务详情也可直接停止。

**小红书管理页配置**　在上一节单页规则基础上，可以配置 views 与 maxPages 支持跨状态、跨页查稿。views 的五个键为 published、reviewing、scheduled、draft、rejected。每个键都需要独立核实的 url、active（当前筛选已生效）、empty（明确的空列表）、next（下一页链接）和 end（明确的页尾标志）。maxPages 为每个状态的最大读取页数，范围 1–100。通道仅跟随同源管理页链接，现阶段支持通过 URL 分页的列表。单页旧配置仍只做正向匹配。页面跳转异常、空白、分页循环、超过页数上限、新增同形态但无法排除的稿件，均不能授权重发。具体生产页面规则尚待真实账号核实。

**任务设置例**　假设首次核对延迟 180 秒、间隔 300 秒、至少 3 次有效核对、缺席窗口 1800 秒，设置重发 2 次、冷却 1800,7200。第一轮即使已经取得三次有效缺席证据，也需等缺席窗口与第一段冷却结束，重新完成最终查重。第二次重发以最近一次提交重新计算缺席证据，整条任务共用原截止时间。账户处于审核中或存在歧义时不累计有效缺席。

**迁移与验收**　迁移 4 为核对记录保存最小覆盖证据，迁移 5 按尝试序号保留各次回执。任务详情的已用次数和上限反映当前快照；GET /api/state 的 publicationIntent.attempts 包含时间、序号与已有回执。受控集成覆盖重启、名额耗尽、最后查重遇到审核稿、停止和最后动作竞争、疑似迟到重复；Chromium 覆盖实际按钮点击计数、跨五个状态的六页列表，以及缺页尾、空白页和分页截断。未执行真实发布。W4 模型恢复、其余平台查稿、宏观内容生产仍待实现。

## 第四轮实施：提交前的模型恢复

自动和人工发布任务在标准 prepare 阶段遇到普通脚本异常后进入 recovering。执行器复用该账号原编辑页生成一次性动作列表，释放全局浏览器锁，再请求规划模型。收到动作后重新获取锁、核验账号、页面、DOM 和标识。模型只能关闭已识别的原生操作提示、将空标题恢复为原任务快照、请求重新走标准准备或交还本人。页面 URL、截图、正文、标题、输入值、账号与凭证均不进入模型消息。恢复后仍走原有的身份、声明和文案检查及持久提交门禁。

工作台任务详情显示恢复调用次数与上限。模型等待期间可从任务详情打开任务浏览器接管，此时旧响应失效；等待本人处理的任务占用该账号，其他账号仍可运行。完成页面操作后点击「本人处理完成，重新核验」，系统在原任务重新检查账号和准备页面。已尝试最终提交的任务继续使用查稿流程。重启中断的恢复转为待人工检查，旧页面令牌失效。

### 配置和启动

在运行服务的 PowerShell 中配置后，进入项目目录运行 npm start。模型服务须兼容 chat/completions 请求、JSON 对象响应及 max_tokens。以下地址和模型名需替换为本机实际配置。

```powershell
$env:MATRIX_MODEL_ENDPOINT = 'http://127.0.0.1:8080/v1/chat/completions'
$env:MATRIX_MODEL_NAME = 'your-model'
$env:MATRIX_RECOVERY_MAX_CALLS = '4'
$env:MATRIX_RECOVERY_MAX_SECONDS = '180'
npm start
```

远程服务使用 HTTPS，鉴权从 MATRIX_MODEL_KEY 环境变量读取。缺少模型配置时，普通异常记录 missing_model。未发现操作能力或需要验证时，任务交回本人。Ctrl+C 停止服务；使用原 dataDir 重启保留恢复预算和提交账本。

可选费用限额使用 MATRIX_RECOVERY_MAX_MICROS（每任务预算）和 MATRIX_MODEL_CALL_MICROS（每请求预留），单位均为模型计价币种的百万分之一。预留值由部署者按供应商价格、请求上限和最多 100 个输出 token 设定；调用前计入，即使超时也保留。它是本地预算估计，实际费用以供应商账单为准。默认仅限制请求次数与时间。迁移 6、7 增加 recovery_incidents 及费用字段。GET /api/state 中 publicationIntent.recovery 包含次数、期限、预留费用和退出原因。POST /api/jobs/{jobId}/human-completed 只接受尚无提交尝试、正在等待本人处理的任务，成功后重新排队。

## 第五轮实施：查稿恢复、重发准备与宏观任务

### 查稿或重发准备异常

小红书管理列表加载失败、出现操作提示、空白列表或筛选状态错误时，只对发生错误的独立管理页生成观察。模型可关闭经识别的原生操作提示，或请求从头重新核对。只有标准核对器重新遍历视图和分页得到的结果才可写入缺席证据。最终点击前查重抛错时记录 inconclusive 并安排下一次检查；该轮不会占用新提交名额。

重发准备异常可在原账号的新提交页恢复。恢复后再次运行标准 prepare 和最后查重。无法确定发布设置入口是否已生效、账号不一致、需要本人验证时，任务转交本人。恢复共用首次准备阶段的调用和费用总额，阶段变化不清零。迁移 9 记录当前恢复阶段。

查看待处理任务详情，点击「打开查稿管理页」处理小红书管理页上的登录或验证；使用「本人处理完成，重新查稿」恢复只读核对，或「停止核对」撤销后续动作。POST /api/publications/{id}/open-verifier、POST /api/publications/{id}/human-completed 和 stop 都使用当前 expectedVersion。管理页需要匹配的本地 xhs-verifier.json 与可显示的账号会话。本人完成后仍须核实作品与账号。未提交稿件的本人恢复继续使用 /api/jobs/{id}/human-completed。

### 运行一个图文或长文任务

启动项目后打开侧栏「宏观任务」。填写主题、定位、事实资料，选择账号与稿件形态，再选择模型可使用的本地图片，可补充图片描述。选择发布方式和预算，保存后点击「立即运行」。从「最近运行」打开各账号成品，可看到独立标题、正文、生成状态以及对应分发任务的状态。模板停用影响未来运行；「停止尚未分发的目标」保留已创建的分发任务。

模型使用前节的 MATRIX_MODEL_ENDPOINT、MATRIX_MODEL_NAME 和可选的 MATRIX_MODEL_KEY，调用结构化 JSON 聊天接口。生成端每次请求最多 2048 个输出 token。输入只含本次主题、定位、事实资料、当前目标和允许使用的素材元数据与描述；不上传图片二进制。部署者如需金额预算，可设置 MATRIX_WRITER_CALL_MICROS 为一次调用的保守预留金额（计价单位的百万分之一），再在模板中设置每次运行的金额上限。费用在请求前持久预留。未配置费率时可使用调用次数预算。生成结果强制 AI 辅助声明；文章按段落转义生成 HTML，图片笔记只可引用本次候选图片。未接入图片内容 OCR、自动标签、语音转写或模板视频渲染。

**调度**　首次发布时间需含明确的 UTC 偏移，后台保存 UTC。只设置首次时间时为单次任务；设置固定秒数间隔时为持续周期。提前量控制何时开始生成。生成完成先保存 ready 成品，发布时间到达才分发。固定时长周期不提供夏令时日历规则。latest 合并错过的周期，只领取最近一期；skip 跳过已迟到一分钟的一期。机器休眠或服务关闭时无法执行。重启使用已创建运行的不可变快照，未确认的付费调用到期后标记 generation_unknown。该状态不自动重新付费。模型服务须支持同步 JSON 响应。

**引用与幂等**　迁移 10、11 创建模板、运行、目标成品和账号素材使用记录。模板版本冲突返回 409。相同模板同一期只创建一次运行，相同手动 requestKey 返回原运行。每个目标独立生成并带稳定的分发键。服务在同一个 SQLite 事务中关联已创建的分发与成品。启用模板和待分发成品保护账号与素材引用。冷却时间按账号计算，可排除其他运行中已预留或近期已分发的图片。
