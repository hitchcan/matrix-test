# Matrix Studio 智能体工作流：实现规划与验收规范

版本：1.0；日期：2026-11-11。适用基线和技术依据见 [01 技术调研报告](./01-技术调研报告.md)。本文的路径、表、接口和状态均为拟新增设计，除明确标注的现有入口外，不能视为已实现。

## 1. 实现范围与优先级

最终范围：宏观任务 → 定时运行 → 素材选择 → 图文/长文/视频生成 → 平台脚本发布 → agent 异常恢复 → 创作中心查稿 → 有限重发 → 结果追踪。

优先交付发布可靠性闭环，再接自动内容生产。这样可用已有稿件验证最关键的新行为，而不是等待视频生成后才发现提交状态模型无法支撑重发。

- P0：业务抽取、迁移、提交 attempts、控制权、核对协议、策略引擎。
- P1：单平台实际 verifier、agent 恢复、可配置重发 UI、重启恢复。
- P2：宏观任务、持久调度、素材理解、图文与长文生产。
- P3：其余平台 verifier、模板视频、长期运行优化。

首个实际适配默认小红书图片笔记；如果没有可用该类账号，改用已有可登录的抖音视频路线。选择变化需记录，不用虚构账号验证结果。不因此放弃四平台最终目标。

时间存 UTC ISO 或统一 epoch，不混用两种单位；对 due_at/state、intent/attempt、观测时间、账号占用等建立索引。状态变更与关键事件同事务提交，防止只更新状态未写证据。

### 历史兼容

1. 历史 publication 未设置 retry policy 时 maxResends=0；不对旧 unknown 自动重发。
2. 旧任务有 submitting 事件但无 attempts 时，迁移为 ordinal=1 的已占用历史尝试；旧 receipt 已有证据保留，不能重新点击。
3. 原 `jobs.state=submitted` 仍表示已有提交回执，不重写成公开成功；新增 publication status 展示追踪状态。
4. 上层状态由 publication_intents 管理，不能因为新增 reviewing/monitoring 导致旧 worker 又领取该 job。
5. 草稿、成品、核对中 intent、冷却待重发 intent 均保护素材引用。账号删除与断开、任务 inspect、人工接管的冲突 SQL 全部检查新状态。
6. 旧发布方式与显式手工模式继续有效。手工确认入口不能绕过统一提交门禁。
7. 旧 requestKey 重复请求输入不同，补 input hash 比对并返回 409；相同请求保持幂等。

## 4. 状态机与结果语义

将“任务执行进度”“发布结果”“浏览器控制权”分开，不用一个 needs_manual 表达全部异常。

运行：scheduled → planning → selecting → generating → validating → ready → dispatching → monitoring → completed/partial/failed；另有 waiting_human、paused、cancelled。

发布意图：prepared → submitting → verifying → reviewing/scheduled/published；验证异常可进入 recovering/waiting_human/unknown；有效缺席可进入 retry_wait → prepared；不可恢复进入 exhausted/failed；多个迟到稿件进入 duplicate_suspected。

attempt：reserved → invoking → acknowledged/unknown/explicit_failed。进入 invoking 前持久化提交名额；reserved 但尚无 invoking 的崩溃可继续同一 reservation，不能创建另一 ordinal 绕过账本。invoking 后崩溃只能查稿。

VerifierResult 定义示意：

```ts
type VerifierResult = {
  result: 'found_published' | 'found_reviewing' | 'found_scheduled'
    | 'found_draft' | 'found_rejected' | 'explicit_submit_failure'
    | 'absent_valid' | 'ambiguous' | 'inconclusive' | 'requires_human';
  checkedAt: string;
  accountIdentity: { expected: string; observed: string; verified: boolean };
  coverage: {
    windowStart: string; windowEnd: string;
    statusesChecked: string[]; pagesVisited: number;
    complete: boolean; truncationReason?: string;
  };
  candidates: Candidate[];
  match?: { externalId?: string; url?: string; evidenceIds: string[] };
  publicVisibility: 'not_checked' | 'visible' | 'not_visible' | 'unknown';
  evidenceIds: string[];
  nextCheckAfterMs?: number;
};
```

Candidate 保存原始标题、平台时间、类型、封面摘要、时长、状态、平台 ID/链接及比对依据。draft、rejected、explicit_submit_failure 是不同分支；原页异常但创作中心存在审核稿时，以实际关联稿件为准，不把原页错误升级成缺席。

## 5. 浏览器恢复接口与动作边界

### Runtime 扩展

```ts
getTaskPage(accountId, intentId): PageRef
getVerificationPage(accountId): PageRef
acquireBrowserLease(accountId, owner, ttlMs): Lease
observePage(pageRef, lease): Promise<Observation>
performBrowserAction(action, lease): Promise<ActionResult>
revealForHuman(pageRef, reason): Promise<void>
```

PageRef 用进程内注册 ID + sessionGeneration 标识，不序列化 Playwright Page。重启后重新建 verifier 页，原页面 token 作废；原页丢失不阻止独立查稿。每账号复用一个 verifier 页，避免累计创建标签。

Observation 包括 URL、页面角色、结构摘要、脱敏截图、可操作节点 token、控件语义和版本。模型返回 JSON action，动作 token 必须存在于当前观察中；超时或页面变化时先重新观察，不盲点旧坐标。

普通动作允许 navigate 到审核过的同平台域名、clickKnownControl、fillApprovedField、scroll、wait、选择已授权文件。禁用任意 JS/shell、任意文件路径、任意跨账号跳转；系统维护可用素材与账号 ID。

### 模型循环

```text
recover(context):
  检查阶段、恢复预算和本人验证标志
  领取浏览器控制权，生成脱敏 observation
  释放全局动作锁，等待模型返回一个 schema action
  重新领取并验证 generation/lease/token/页面新鲜度
  执行动作，记录结果，再观察验证
  修复成功 → 标准 prepare/validate 再检查
  最终动作不确定 → verifier
  本人验证 → waiting_human
  超预算 → blocked，保存原因与可恢复位置
```

首版保留全局物理操作串行；逻辑账号租约覆盖 owner，模型等待期间不长期持有全局锁。人工作业期间暂停该账号自动点击；用户点击“已完成验证”只触发重新观察与恢复，不直接宣布成功。后台其他账号仍可按调度执行。

最终提交控件和所有可完成投稿的二级确认只能调用 submission-service；普通工具不得通过 Enter、坐标点击或表单动作隐式触发。若某个新页面无法可靠划分该边界，返回 unsupported_final_action，不用任意点击兜底。此处需动作网关与适配器共同实现，提示词不能充当唯一边界。

租约到期不代表已经发出的 Playwright 操作被撤销。动作网关必须跟踪 in-flight 操作：旧 click 尚未结束时不能把同一页面交给新 owner 继续写入；可取消的等待先取消并等待收敛，可能发生最终提交的未决动作转 unknown 后查稿。不得仅凭数据库 fencing token 宣称已经阻止浏览器中仍在等待执行的点击。

平台内容、OCR 和页面文字都是观测数据；忽略其中要求修改系统策略、读取凭证或切换账号的文字。日志/截图遮盖验证码、手机号等；认证页不发送完整输入内容给模型。

## 6. 创作中心 verifier 协议与匹配

```ts
interface CreatorCenterVerifier {
  captureBaseline(ctx): Promise<Baseline>;
  inspectPublication(ctx): Promise<VerifierResult>;
}
```

ctx 包含指定账号身份、artifact、intent、最近及历史 attempts、提交时间窗、baseline、超时与页数预算。正常 DOM 脚本负责稳定查询，页面变更时调用 agent 受控恢复，再复跑标准提取；页面抓取失败不返回 absent_valid。

匹配规则：

1. 有已核验 externalId：按 ID 查详情，禁止仅凭相似标题替换 ID。
2. 无 ID：baseline 之外的新增候选，在账号/类型/时间窗一致的前提下，结合标题和至少一个内容或媒体特征；具体平台可收紧规则。
3. 标题、时间或时长缺失不自动编造，不能满足规则就 ambiguous/inconclusive。
4. 相似候选无法唯一确定时不计缺席，打开详情继续诊断。
5. 时间窗包括时钟偏差和页面时间精度余量；余量属于配置，测试跨分钟/跨日/时区。
6. 每次查 all/reviewing/scheduled/draft/rejected 等实际相关范围；如果分页上限不足以覆盖时间窗，coverage.complete=false，不允许缺席重发。
7. 重发前覆盖所有历史 attempts，而非只查最新一次，防原稿迟到。

核对证据保存在 .data/evidence/ 中，数据库保存引用；不包含 Cookie/token。完整脱敏截图保留期、最大空间可配置；超过保留期可以清理图片，但保留最小审计结论。样例证据不能来自真实凭证文件。

## 7. 重发策略与原子提交协议

以下为新任务配置示例；字段需 schema 校验，数值不是平台推荐或防风控保证。

```json
{
  "recovery": {
    "enabled": true,
    "maxRoundsPerIncident": 2,
    "maxActionsPerIncident": 12,
    "maxIncidentDurationSeconds": 180
  },
  "verification": {
    "enabled": true,
    "firstCheckAfterSeconds": 180,
    "checkIntervalSeconds": 300,
    "absenceWindowSeconds": 1800,
    "requiredValidChecks": 3,
    "lastCheckFreshnessSeconds": 30,
    "maxObserveDurationSeconds": 86400
  },
  "retry": {
    "maxResends": 2,
    "allowAbsentAfterTimeout": true,
    "cooldownSeconds": [1800, 7200],
    "retryDeadlineSeconds": 21600,
    "retryExplicitTransientFailure": true,
    "retryRejectedContent": false
  }
}
```

maxResends 允许 0，表示不重发。新任务 UI 默认可预填 2，服务端缺字段使用 0，旧任务始终不悄悄启用。cooldownSeconds 的长度至少为 maxResends；拒绝负数、非整数、NaN、过大数组或窗口与截止时间矛盾。字段单位在 UI 展示转换，存储统一秒。

absence 检查必须从同一 attempt invokingAt 之后累计，requiredValidChecks 在至少 checkIntervalSeconds 间隔下成立；总 span 不能通过同一秒反复刷新凑数。缺席窗口基于 invokingAt，是否有效以覆盖范围判定。网络失败不增加计数，也不重置总 deadline。出现 reviewing/scheduled 候选立即停止缺席分支。draft 尝试恢复原稿而不是新建副本，仍消耗一次最终提交名额。

computeRetryDecision 为纯函数：

```ts
computeRetryDecision({ intent, attempts, observations, now, accountState }): {
  action: 'wait' | 'verify' | 'recover' | 'resume_draft'
    | 'resubmit' | 'stop' | 'human';
  reasonCode: string;
  nextDueAt?: string;
  evidenceIds: string[];
}
```

模型可建议动作，不能修改计数或宣布满足硬条件。所有来源，包括 UI confirm/retry、规划 agent、恢复 agent、自动 worker，统一走同一 gate。

最终提交序列：

1. 检查 intent 未完成/取消、账号正确、artifact 与策略快照有效。
2. 初次提交采集 baseline；重发在账号写锁下完成最后查重，结果新鲜且覆盖全部 attempts；等待任何模型调用后如证据过期，再查一次。
3. SQLite 短事务重新读取 intent.version/当前租约/attempts，校验次数、截止时间、冷却和证据版本，创建唯一 ordinal reservation；同时写事件。事务不跨浏览器/模型网络等待。
4. 所有预检完成后，短事务将 reservation 置 invoking 并落库。此刻占用一个最终动作名额；随后最多发出一次最终提交动作。
5. 取得回执更新 acknowledged；超时或进程中断更新/恢复为 unknown；创建后续查稿计划。不因收到错误就退还 invoking 名额。
6. 并发重复请求返回已有 attempt 或 409，不创建第二次动作；fencing token 失效的 owner 在动作网关被拒绝。

一个 attempt 表示一次逻辑最终提交动作；有明确二级确认的流程，在同一 attempt 中记录子动作，禁止重新进入完整提交链。不能把验证码后继续原提交误计为重发，也不能借此重复创建稿件。

现有 adapter.submit(account,content,onClick,hooks) 的 onClick 是同步回调，不能直接塞入异步落库/策略检查后不等待。实施时增加明确 await 的 onBeforeFinalAction/执行网关接口，在每个可能最终生效的动作前等待 gate 成功；所有平台专用流程和原手工 confirm 一并接入。测试必须证明 gate reject 时 button.click 调用次数为 0，gate 尚未完成时也不会抢先执行。

修改文案/生成新 revision 不重置同一次 release intent 的次数；重发默认复用原 artifact，避免事实漂移。拒绝后修订需单独开启策略，并保留 lineage 和原 intent 限额。耗尽后 stop，显示完整 attempts；不能自动换 requestKey、换账号或创建新 run 绕限额。

## 8. 服务接口和前端要求

推荐先实现内部服务；HTTP 复用原 X-Studio-Token、本机与同源校验。所有工具返回结构化 reasonCode，不把原始异常栈或凭证传到模型。

拟新增 API：

| 路由 | 行为 |
|---|---|
| POST /api/task-templates | 创建模板，验证账号/形态/素材/策略，保存版本 |
| POST /api/task-templates/:id | 更新未来运行配置，已有运行快照不变 |
| POST /api/task-templates/:id/run | 立即运行，带 requestKey 去重 |
| GET /api/runs/:id | 返回步骤、各账号成品和 publication 摘要 |
| POST /api/publications/:id/verify | 请求核对，有检查节流，不触发直接提交 |
| POST /api/publications/:id/recover | 请求 agent 恢复，服从 owner/预算/阶段 |
| POST /api/publications/:id/request-retry | 请求策略评估；绝非无条件重发 |
| POST /api/publications/:id/human-completed | 结束用户接管后重新观察，防重复执行 |
| POST /api/publications/:id/stop | 停止后续动作，已提交作品保持不动 |

更新操作带 expectedVersion，冲突返回 409。missing model、unsupported verifier、needs_human、limit_exhausted、coverage_incomplete 等必须可区分。API 不允许模型通过 body 提交 observedAccountId/absence=true 等自证事实；这些由核对服务生成。

前端要能设置生成提前量、时区、宏观目标、账号/内容类型、素材范围、预算、恢复与核对/重发参数。任务详情显示：当前 owner/阶段、agent 正在做什么、待本人验证原因、上次核对、发现的作品状态、提交次数“已用/上限”、下一次核对/重发时间、停止按钮和证据。

区分“已提交”“审核中”“后台已发布”“已核验公开可见”“结果不明”“重发耗尽”；移除将所有 unknown 都描述为永久禁止自动重发的旧文案，但保留旧任务与不满足策略时的禁止解释。

## 9. 内容生产与调度实现契约

TaskSpec 包含 topic、styleProfile、事实资料范围、schedule/timezone、prepareLeadSeconds、latePolicy、target account IDs/types、素材集合与冷却、generation、budget 和 publicationPolicy。不允许模型执行时擅自换账号或扩大素材范围。

每个 run 按 (accountId,slotKey) 生成一个或多个完整 artifacts，分别调用 dispatch-service；不要挤进单一 content.type。若同一平台不同账号内容不同，拆独立 dispatch 或以完整 artifact 覆盖输入，不再依赖平台 title/body 覆盖。

Scheduler 保存下一次运行、准备、发布、检查和重发的 dueAt；用条件 UPDATE 领取，过期租约恢复。每次 await 返回后检查取消标记/版本。仅准备阶段安全步骤可重跑；已 invoking 必须查稿。定时模板编辑不导致相同 scheduledFor 的重复运行；已创建 run 继续其快照。

内容生产第一版：图片/视频元数据 + 可人工校正标签 → OCR/转写摘要 → 硬过滤/全文检索 → 模型结构化选材 → 文案 → 模板卡片/标准文章 HTML → 校验 → 回库。素材不足进入可说明的 blocked 状态，先让 agent 在允许范围尝试替代。

视频版追加关键帧/镜头索引、带时间码剪辑计划、ASR/TTS、FFmpeg。子进程使用参数数组，无 shell 拼接；渲染放独立 worker，输入只能引用已授权资产。生成外部任务保留 remote_task_id，恢复时先查远端，成本达到上限不再继续生成。

## 10. 分阶段工作包与完成定义

工程量为单名熟悉项目开发者的人日粗估，不含账号权限审批、验证码等待和模型费用。可用 demo 跑工程闭环，但最终真实联调需明确区分。

| 工作包 | 依赖 | 内容与完成定义 | 粗估 |
|---|---|---|---|
| W0 基线与能力盘点 | 无 | 读取本套文档/本地指令；运行现有检查；列出每平台发布/核对真实能力；保留用户改动 | 1–2 |
| W1 服务与数据库 | W0 | 迁移可重复、旧记录兼容、抽取 dispatch/submission 服务、运行/attempt/event 事务和引用保护 | 3–5 |
| W2 受控提交与调度 | W1 | gate、计数、租约、时间、断点恢复、纯策略函数；fake verifier 下覆盖原子边界 | 4–6 |
| W3 首个平台查稿 | W2 | baseline、内容管理分页/状态、详情匹配、有效缺席和歧义；固定页面和真实账号证据 | 3–6 |
| W4 Agent 异常恢复 | W2 | gateway、schema action、观察/动作/复核、原会话接管、验证码暂停；真实模型 + fake 测试 | 4–7 |
| W5 闭环 UI 与首版验收 | W3,W4 | 已有稿件触发发布→恢复→查稿→有限重发，次数/冷却/停止可用，重启不重发或清零 | 3–5 |
| W6 宏观任务与图文长文 | W5 | 持久周期、素材索引、模型选材生成、多账号 artifacts、预算与完成汇总 | 7–12 |
| W7 其余平台核对 | W5 | 逐平台实际适配与 fixtures；无法验收通道明确禁用，不假装通用完成 | 6–12 |
| W8 模板视频 | W6 | 时间码、配音字幕、渲染、封面、多比例与质量校验 | 8–15 |
| W9 试运行与优化 | W6,W7,W8 | 7–14 日观察窗口、失败样本回归、成本与介入原因统计 | 3–6 人日，另计观察期 |

W0–W5 是第一个交付里程碑，不包含素材自动生产；W6 完成图文长文宏观任务，W8 才完成本期模板视频目标。完整工程约 42–76 人日粗估；按实际账号与适配难度修订，不把全部目标描述为几天即可完成。

## 11. 必须覆盖的验收场景

每项需说明使用 unit/fake、受控 Chromium、真实账号哪一种证据；禁止用真实账号批量制造重发验证次数。

| 编号 | 场景 | 预期 |
|---|---|---|
| A01 | 旧数据库迁移并二次启动 | 无记录丢失、无重复 attempt、旧 unknown 不自动重发 |
| A02 | 同 key 同内容/不同内容 | 前者复用；后者 409 |
| A03 | 两个调用同时请求同 intent 提交 | 仅一个最终动作 |
| A04 | invoking 后进程中断 | 重启查稿，不重复该 attempt |
| A05 | reservation 后未 invoking 中断 | 恢复原 reservation，无额外 ordinal |
| A06 | maxResends=0/2 | 最多 1/3 次最终动作 |
| A07 | 点击超时 | 名额不退还，进入验证 |
| A08 | 次数耗尽后换 key/revision | 不能自动绕过原 intent 次数 |
| A09 | 审核中/定时作品 | 停止缺席重发，继续监控 |
| A10 | 创作中心失败、登录跳转、空白页 | 不计 absent_valid |
| A11 | 仅第一页但时间范围未覆盖 | coverage=false，不计缺席 |
| A12 | 同标题历史稿/两个相似候选 | 不误关联为本次成功，不判缺席 |
| A13 | 足量有效检查、窗口和冷却到期 | 最后查重后仅触发一次新 attempt |
| A14 | 短时间反复检查 | 不凑满最小间隔 |
| A15 | 重发前旧稿出现 | 取消待发 attempt，不新建稿 |
| A16 | 两次都已发后发现旧稿迟到 | duplicate_suspected，停后续尝试，不自动删稿 |
| A17 | 草稿存在 | 优先恢复原草稿，最终动作计数正确 |
| A18 | 审核拒绝/临时提交失败 | 原因分类不同，按各自策略处理 |
| A19 | 脚本定位失效、可识别弹窗 | agent 恢复后标准校验通过才继续 |
| A20 | agent 请求过期 token/旧 lease | 动作拒绝，重新观察 |
| A21 | 普通工具点击发布/Enter 提交 | 被门禁拦截或转受控提交，无次数绕过 |
| A22 | 验证码/扫码/安全挑战 | 保留原会话等待本人，不读取验证码、不重复提交 |
| A23 | 模型等待期间另一账号任务 | 不长期占全局浏览器锁 |
| A24 | 身份不一致 | 阻断写入，不自动换绑 |
| A25 | recovery 步数/时间/费用超限 | 停止循环并保存原因 |
| A26 | 关机后重启、错过多个周期 | 按 latePolicy，不卡死、不瞬发全部积压 |
| A27 | 模板编辑与同 scheduledFor 触发 | 不重复 run，已有 run 快照不变 |
| A28 | 一任务三形态、多平台和同平台多账号 | artifact 媒体隔离，成功目标不重发 |
| A29 | 素材不足/超预算/异步模型响应丢失 | 有限恢复，先查远端，不无限付费 |
| A30 | 核对中删除素材/账号 | 受引用保护，符合终止后清理规则 |
| A31 | 取消或 stop 与冷却动作竞争 | 原子检查，不再启动新的最终动作 |
| A32 | 日志与模型观察 | 无 Cookie/token/验证码，截图脱敏 |
| A33 | 重启丢失原 Page 和内存 Map | 能重建 verifier 页核对，不能声称恢复原提交页 |
| A34 | 后台已发布但公开未知 | 分开展示，不能冒认匿名可见 |

现有 npm run check、npm test 必须通过；新增模块加入语法检查脚本，新增测试采用可控时钟，不等待真实几十分钟。原旧“未知禁止盲重试”测试保留；新增满足策略的受控重发测试，两者通过不同入口和权限条件共存。不得通过删除测试降低约束。

## 12. 交付清单与检查方式

- 代码、迁移、必要依赖锁文件、配置示例；不提交 .data、真实截图凭证或 API 密钥。
- 每个新接口有输入/输出及 reasonCode 示例；任务参数与 UI 单位一致。
- 测试结果、已支持能力矩阵、真实验收与受控测试分列。
- 演示流程：给定稿件 → 脚本故障 → agent 恢复 → 成功查稿；另用受控页面展示有效缺席 → 冷却 → 有限重发 → 耗尽。
- 宏观任务流程：定时 → 自动选材 → 图文/长文/模板视频 → 各账号提交与状态汇总。
- 运维说明：启动/停止、睡眠限制、模型配置、日志/证据保留、崩溃恢复、停用自动重发和待本人验证恢复。
- 已知限制：无法获权、未验收页面、暂不支持形态与未完成工作包必须明确列出，不能用“Agent 会自行处理”代替实际实现。

文档阶段不创建真实任务、不改当前发布逻辑；实施阶段以每个工作包的完成定义和最终全范围目标推进。
