## 使用

1. 在账号管理选择快手，添加后在独立 Chrome 中自行扫码。身份读取只认可本人快手号或官方当前账号响应，不以昵称、头像或 Cookie 存在证明身份。
2. 内容工作室选择一个视频及快手账号。快手只有一个作品描述框，因此使用标题、换行和简介合并填写；相同标题与简介只写一次。支持快手独立文案。
3. 勾选 AI 时选择“内容为AI生成”；不勾选时保留其他非 AI 声明，仅清除已有 AI 声明。必须读回一致且菜单关闭才继续。
4. 自动/人工模式沿用工作台原流程，最终点击仍通过原持久提交门禁。提交前复核身份、文案及声明；异常暂停。
5. 官方页出现本次“发布成功”提示才确认提交，不虚构稿件 ID、链接或审核状态。点击后回执不明则等待人工核对，禁止自动重发。

本机定时继续使用原模板调度器；快手后台必须选择“立即发布”，人工改成原生定时则暂停。封面沿用平台自动生成或用户人工处理；查看权限、互动开关、地点、活动及商业服务不自动更改。

## 2026-11-17：身份核验失败修复

现场：扫码登录后账号一直停在「等待扫码 / 识别登录」。原因有三处，均出在身份读取而不是登录本身：

1. 快手账号接口的匹配用了精确路径且要求没有查询参数（`url.pathname===...`、`url.search` 为空）。平台实际会给自己的接口追加缓存/签名参数，导致响应根本不被采信。
2. 身份监听只绑定了打开时的那一个标签页。扫码后如果平台把登录结果落到新标签页，原页永远收不到 `account/current` 响应。
3. 账号卡片的快手号只从悬停卡片 `.header-info-card .user-kwai-id` 读取，悬停未展开时读不到。

修复：路径改为按模式匹配（允许查询参数），响应字段兼容 `userId/user_id/uid` 与 `userKwaiId/user_kwai_id/kwaiId`，仍要求明确的已登录标记或合法 ID；身份监听扩展到该账号浏览器环境的所有标签页；DOM 兜底增加「快手号：xxx」文本读取。同时新增失败诊断日志：核验失败时终端打印页面地址与最近请求路径（每个账号最多 30 秒一条），便于对照真实页面继续适配。

受控测试 `test/platform-identity.test.mjs` 覆盖带查询参数的账号接口、未登录标记、非账号接口与其他作者字段不采信。

## 2026-11-18：已提交却记为「结果待确认」

现场：任务 16:40 点击发布，作品实际已提交成功，但任务状态变为「结果待确认（unknown）」，事件消息里的诊断为：

```
/rest/cp/works/v2/video/pc/publish/refresh HTTP 200 result=1 code=未知（连续三次）
```

原因：`watchKuaishouSubmission` 只接受**精确路径** `/rest/cp/works/v2/video/pc/submit` 的 `result=1`。现在控制台的发布请求走 `/pc/publish` 系列（实际观察到 `/pc/publish/refresh`），路径不匹配，成功响应被当成普通刷新丢弃，45 秒后按「未取得明确成功提示」转待确认。

修复：

- 接受路径改为 `/rest/cp/works/v2/video/pc/(?:submit|publish)`，包含 `/publish/refresh` 等子路径；
- 判定条件为 2xx 且信封明确成功（`result===1` 或 `code===0`）；
- 回执证据写入实际命中的接口路径，便于事后核对；
- 诊断信息增加响应 `data` 的键名，以及超时时当前页面地址，便于下一次定位。

安全边界不变：仍只接受 `cp.kuaishou.com` 同源、本次点击之后、POST 且信封成功的响应；页面文案或其他来源不作为成功依据。

受控测试新增「快手接受 /pc/publish 系列成功响应（含 refresh 子路径）」：`result=0` 不接受，`result=1` 接受且回执包含命中路径。原有的「只接受本次官方 POST」「toast 提前消失仍能捕获」用例继续通过。
