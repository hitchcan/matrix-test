# 任务目标约束的坐标恢复

2026-11-13。扩展现有账号标签页视觉恢复，继续使用 Playwright 截图和鼠标操作，不依赖 Windows 桌面控制。

## 使用及触发

沿用“恢复、预算与发布后核对 → 结构化恢复失败后启用账号标签页视觉操作”，agent 配置需支持并启用图片输入。原有 visualEnabled=false 的任务不增加权限；已启用视觉恢复的任务在后台加载新代码后可以使用目标约束坐标操作。

服务从不可变稿件快照和标准准备的失败环节生成可信目标。目前支持：

- 抖音视频可见范围：仅在任务明确指定 public/private、且该步骤失败时，允许实现指定的公开或仅自己可见。
- 创作声明：根据任务实际 AI 辅助创作选择，允许选择对应声明；选择不声明时可取消已有 AI 复选项。
- 图片上传故障：允许展开相关界面、观察后请求 retry_image_upload，实际文件上传交回标准工具。

没有明确目标的故障、创作中心核对页继续沿用原安全按钮视觉能力，不任意推断分区、封面、授权或账号设置。选择 manual 的任务仍在最终发布前等待人工确认。

## 模型操作协议

观察提供 coordinateMode=true、可信 goal、截图、CSS像素 viewport、当前相关选择状态和上一步结果。模型可自行根据画面指定坐标，不需要 targetId 或程序提供按钮坐标列表：

```json
{"action":"click_at","token":"当前观察token","goal":"visibility","x":420,"y":360}
```

goal 必须与当前可信目标种类一致，x/y 必须为视口内整数；不能附带选择器、脚本、文字输入、文件或网址。支持 scroll(up/down)、revalidate、human，以及图片目标的 retry_image_upload。

模型一次选择一步动作。点击后必须重新观察，相关设置看似完成时选择 revalidate，由标准适配器独立读回，再进入原有准备/身份/文案/声明/持久提交门禁，不能由模型自行宣布完成发布。

## 目标范围与画面

画面保留相关设置行、可展开的设置入口和由本轮操作打开的目标菜单文字。账号导航、正文输入、媒体、验证码及显式敏感区域保持遮盖；匹配手机号或邮箱的相关文字也遮盖。页面内容始终是不可信数据，不构成授权。

坐标不需要命中预先列出的按钮，但执行前会对实际命中的 DOM 元素做分类：必须在当前目标区域或允许的本地展开入口，或是本轮已打开菜单中的目标值。可以点击陌生外观的组合框、展开控件和目标选项；不能借目标“仅自己可见”选择“好友可见”、操作相邻“保存权限”或更换账号。

当前无法可靠分类的画布、iframe、任意位置及未知动作会拒绝，不是任意桌面或整页无约束鼠标代理。没有找到可辨认目标区域时应交回标准流程或人工处理。

## 操作边界和预算

每个截图绑定当前账号 session、任务标签页、文档、URL、一次性 token、视口和滚动状态。DOM变化、用户输入、滚动、窗口变化、换页/换账号及停止后迟到回复均不能继续使用旧坐标；点击过程中检查命中元素及事件路径，防止遮挡或误点。自定义门户菜单还要求来自同一目标、同一文档中最近的已执行操作。

最终发布/提交、删除、支付、账号安全、登录、验证码和授权不开放。坐标阶段阻断当前页新网络请求（包括GET）及主页面导航，关闭该页打开的新窗口；有 Service Worker 控制或出现身份验证时不截图，转人工。这些限制可能使依赖在线请求的菜单无法展开，此时需回到标准适配器，不通过自由点击绕过发布门禁。

沿用原有阶段升级阈值，以及持久化的调用次数、费用和时间上限，不重置已用次数或过期窗口。默认总恢复上限仍为4次、180秒；两次结构化调用后只剩两次视觉调用，多步探索可能耗尽预算。可按实际需求调整升级前结构化次数，或启动环境 MATRIX_RECOVERY_MAX_CALLS / MATRIX_RECOVERY_MAX_SECONDS；不把生成任务的 maxCalls 当作恢复预算。已有 incident 使用原保存上限。

日志记录可信目标、坐标及执行/阻断结果，不记录截图或凭证。动作失败会把上一步结果交给下一次观察，仍占用原模型调用预算。
